## 5. Critique

Reviewed as the two users the system serves.

**An agent building a page.** It can now answer "which component, and may I use it here" from one entry: purpose, use, avoid, API and source, in the same words on the site and in `REFERENCE.md`. Values cannot drift because nothing is hand-synced. The remaining ambiguity is honest and listed: radius, the primary button colour, the audience noun, the archetype, icons and the logo files.

**Tumai reviewing the site.** The system reads calmer: one gradient moment per view, fewer colours, one heading size, cards with distinct jobs, widgets that move only when seen. Open decisions sit on the Checklist page with what happens until each is made.

**Still weak.**

- One very long page (23 sections). The rail and jump menu carry it, but separate routes would make sharing a section easier.
- The JavaScript ships as one 690 kB chunk (192 kB gzipped). Lazy-loading the image library and widgets would cut first load.
- The command hero's product preview is a coded mock until a real screenshot exists.
- A few widget samples use round numbers (50%). They are labelled sample data, but less tidy figures read more real.

## 8. Softer widgets and cards

Tumai asked for every widget and card to use a lighter tone, so nothing reads too poppy.

- `src/components/widgets/tones.ts` is now the one colour source for widgets: light (200) for bars, rings, tiles, chart marks and selected states, soft (50) for tile ends, bar starts and tints, and a light brand sweep for progress fills and gauges. No widget uses a full-strength shade for data.
- Stat and countdown tiles, avatars and funnel steps run 200 into 50 with ink text. Rings, gauges, ticks, the heatmap, bars, stars and progress fills use 200. Today, selected slots, finished steps and toggles use rose-200 with ink text.
- Cards: feature card icons, overview dots, seat bars and preview dots use 200. The featured pricing card has a rose-200 edge and soft check marks.
- Kept at full strength: primary buttons (including the plan card and timer controls), checked form controls, focus rings, and the green live dot, which reports a real state.

## 10. The video player

Tumai supplied a video player component and set it as the only video UI style in the system.

- `src/components/ui/video-player.tsx` now holds that player. The video has clean rounded edges and nothing around it: the old hairline frame, soft-wash placeholder, native controls and corner mini-player are gone.
- Its styling uses tokens: the translucent `#111111` panels became `carbon/60` and `carbon/80`, `rounded-xl` and `rounded-2xl` became `rounded-lg`, and `text-sm` became the label role. The supplied shadcn `Button` was not copied in, because the system's own `Button` lives at the same path; the controls are small buttons inside the player.
- Added for use without a mouse: the control bar also shows on keyboard focus and while paused, the seek and volume tracks are keyboard sliders, and every control has a label. Play state follows the video's own events, and the duration shows before playback starts.
- `overview.mp4` itself has a pastel frame recorded into every frame (25px at the sides and 57px top and bottom at 1920 × 1080) and a stray dot in its first frame. The player's new `crop` option trims those edges on screen (6% top and bottom, 2.6% each side), and an edge scan across nine points in the video found no frame pixels left. Re-exporting the file without the frame would make the crop unnecessary.
- The blurred control bar is recorded as a deliberate departure from the no-glass direction.
